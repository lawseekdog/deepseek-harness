# Agent Note: 明确不完整的会话搜索

Status: proposed

[English](2026-09-05-explicit-incomplete-session-search.md) | 中文

## Problem

保留会话中的未知必需事件会使 SQLite 全库核对失败。日志完整，但当前运行时无法解释。删除日志会丢失证据，接受旧事件名会绕过执行拒绝。

## Proposal

搜索页必须返回 `coverage` 和 `unsupported_sessions`。仅在检查已枚举会话时出现 `SessionFormatUnsupportedError` 才产生不完整覆盖；其他故障拒绝查询。保留会话及原始字节，只删除失效的派生索引行。不支持的目标仍拒绝精确搜索及继续执行。复用上一进程的索引前先验证持久化日志，跨会话游标绑定覆盖变化。

API 与客户端传递覆盖状态。消费者独立授权不支持的会话 ID；即使无法公开任何 ID，仍保留不完整状态。原始路径、异常文本与未获授权的数量不得越过权限边界。

## Alternatives considered

**恢复已退役事件名称。** 接受名称不能恢复语义，且可能让缺少语义的会话继续执行。

**删除或隐藏历史会话。** 这会移除失败证据，也无法应对下一次事件变化。

**返回健康命中而不说明覆盖范围。** 调用者可能误以为不完整结果来自完整会话库。

## Acceptance criteria

真实 JSONL 字节不变，仍可枚举，准备执行仍被拒绝。存在不支持会话时，健康命中与空结果均标记不完整。一般持久化故障拒绝查询。重启验证阻止返回旧索引中的不支持日志命中。API 与客户端限制 ID 并保留覆盖状态。集成前必须验证生成的 Typert 编解码器与构建产物保留必填字段。

## Risks

重启后的首次搜索工作量增加。不支持的日志会持续复查，不创建第二套持久化状态。后端连元数据都无法枚举时，搜索仍整体失败。本补丁不提供事件注册或迁移机制，也不扩大无法读取历史身份的会话权限。
